- **Parser**: `CREATE OR REPLACE FUNCTION` with an `AS $$ ... $$` body now parses when no dialect is set. The generic end-of-statement scan treated the `REPLACE` of the header as a MySQL-family `REPLACE` statement and ended the `CREATE` there; a word following `OR` is now always part of the current statement (`OR REPLACE` / `OR ALTER` headers, and nothing valid ends an expression with a bare `OR`). The MySQL dialect keeps its own `REPLACE INTO` statement.
