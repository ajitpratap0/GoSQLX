- **Parser**: SELECT now accepts a limit clause after the locking clause, the PostgreSQL order `SELECT ... ORDER BY x FOR UPDATE SKIP LOCKED LIMIT n`. After `FOR UPDATE` each of `LIMIT` / `OFFSET` / `FETCH FIRST` may appear at most once, in any order; `OFFSET` combines with either, but `LIMIT` and `FETCH` are mutually exclusive, and a limit-clause token on both sides of the locking clause is invalid — all verified against libpg_query. The SQL-standard order `LIMIT ... FOR UPDATE` was already accepted; MySQL keeps its own grammar (`FOR UPDATE ... LIMIT` stays rejected there, as MySQL puts `LIMIT` first).
